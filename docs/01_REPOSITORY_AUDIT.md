## 1. 감사 대상

파일 8개, 1.1 MB. 소스 파일은 존재하지 않았다 — `index.html`(661줄)과 `assets/atlas.webp` 두 개의
빌드 산출물, 문서 4개, 그리고 죽은 워크플로 하나가 전부였다.
v0.8 문서 §9가 "권장"한 `src/battle.js`, `data/parts.json` 등은 하나도 구현되어 있지 않았다.

## 2. 측정된 사실

### 2.1 아틀라스 좌표계 불일치

```
코드가 선언한 크기 : 2048 × 2999
실제 파일 크기     : 1024 × 1500
알파 채널          : 없음
```

CSS가 백분율 기반이라 화면이 깨지지는 않았지만, 모든 스프라이트가 의도한 해상도의 절반으로 렌더됐다.

### 2.2 아틀라스 영역의 1/3이 비어 있었다

32개 좌표 영역을 잘라 평균 휘도를 측정한 결과, **10개 영역이 100% 검정**이었다:

`icon_box_shell`, `icon_eye_sticker`, `icon_spear`, `icon_tape_roll`, `icon_mug`,
`icon_patch`, `icon_umbrella`, `icon_ghost`, `icon_ribbon_red`, `icon_scissors_red`
(+ `prop_tornpaper_right` 70% 검정)

이 10개가 **조립 UI의 파츠 선택 아이콘 전부**다. 게임을 열면 가장 먼저 보이는 UI가 검은 네모 10개였다.
좌표 맵과 이미지가 서로 다른 버전에서 생성되어 동기화가 깨진 상태였다.

재현: `npm run assets:reference` — 결과가 `assets/source/reference/legacy-atlas-report.json`에 기록된다.

### 2.3 "파츠 레이어"가 스프라이트가 아니었다

`part_*` 엔트리는 캐릭터에 겹쳐 그리는 레이어로 쓰였지만, 실제 내용은 레퍼런스 스크린샷을
사각형으로 자른 **불투명 크롭**이었다. 알파가 없다.

- `part_tape_roll` — UI 라벨 행의 크롭. `"PE"`, `"EY"` 글자가 그대로 들어 있다
- `part_eye_sticker` — `"ICKER"` 글자가 들어 있다
- `part_box_shell` — 나무 막대기와 종이 배경. 박스 껍질이 아니다
- `part_scissors` — 가위 + 캐릭터 몸통 + 폭탄이 함께

즉 전투 화면에서 캐릭터에 파츠를 겹치면 **종이 배경과 UI 글자가 있는 불투명 직사각형**이 붙었다.

## 3. 구조적 문제

| # | 문제 | 결과 |
|---|---|---|
| 1 | 파츠 효과가 엔진 전역에 하드코딩 (`state.build.X === 'y'` 27곳) | 파츠 1종 추가에 파일 전역 수정. 목표치 32종은 비현실적 |
| 2 | 시드 없는 `Math.random()` 8곳 | 회귀 테스트·버그 재현·밸런스 시뮬레이션 전부 불가 |

| 6 | 모듈·타입·테스트 인프라 0 | 리팩터 안전망 없음 |

## 5. 레퍼런스와 구현의 차이

레퍼런스는 **링 노트 위의 종이 스티커**를 보여준다. 캐릭터가 화면의 주인공이고, 4단 아이콘 액션 레일이
있고, 테이프·클립 장식이 붙어 있다.

v0.8은 이 레퍼런스의 **색상 팔레트만** 가져오고 화면 밀도·위계·촉감은 가져오지 않았다.
그리고 레퍼런스를 분해해 쓰는 대신 **전체 스크린샷을 통째로 배경에 깔았다**
(`.bg-art { opacity:.78; mix-blend-mode:multiply }`).
그 위에 420 px 정보 카드가 390 px 히어로의 상반신을 덮고 있었다.

## 6. 모바일 · 테스트 가능성

- breakpoint 3개, 그중 `860px` 블록이 4곳에 중복 선언. 860 px 이하에서 `.hero-figure`가 390 px 고정
  폭이라 잘리고, 파츠의 픽셀 앵커가 고정이라 몸에서 떨어져 보였다. **데스크톱만 실사용 가능**
- 테스트 0개. 쓸 수 없는 구조적 이유: IIFE라 import 불가, 결정론 없음,
  규칙 함수가 `document.getElementById`를 직접 호출, 전역 싱글턴이라 격리 불가

## 7. 결론

부분 개선으로는 §2와 §3-1/2/3을 해결할 수 없었다. 좌표 맵과 이미지의 동기화 파괴는
"아틀라스를 손으로 편집하는 워크플로" 자체의 산물이고, 파츠 효과의 산재는
"효과가 데이터가 아니라 코드"인 데서 나온다. 따라서 구조를 바꿨다.
