# 08 — 테스트 계획

## 1. 현황

```
npm test          →  8 파일, 132 테스트 (단위 + 통합 + 컴포넌트)
npm run test:e2e  →  15 테스트 (Playwright, Chromium 1440×900)
npm run typecheck →  tsc --noEmit, strict
npm run simulate  →  밸런스 배치 시뮬레이션 (테스트가 아닌 측정 도구)
```

v0.8은 테스트 0개였고, 쓸 수도 없었다 — IIFE라 import 불가, 결정론 없음,
규칙 함수가 DOM을 직접 호출, 전역 싱글턴이라 격리 불가.

### `components.test.tsx` (12, jsdom)

렌더 계층에서 게임의 두 핵심 주장을 검증한다.

- `Sprite` — 논리 ID가 카탈로그 파일로 해결되는지, 장식 이미지가 `aria-hidden`인지,
  **모르는 ID가 슬롯 placeholder로 떨어지고 누락 레지스트리에 기록되는지**,
  로드 실패 시 선언된 fallback으로 교체되는지
- `PeelbeastFigure` — 슬롯마다 레이어가 하나씩 생기는지, 빈 슬롯은 레이어가 없는지,
  **박리된 슬롯의 레이어가 DOM에서 사라지는지**, 위치가 카탈로그 앵커 계산과
  픽셀 단위로 일치하는지, z 순서가 지켜지는지, 앵커 오버레이가 개발 모드에서만 나오는지

## 3. 통합 테스트

`fullRun.test.ts` (13) — 모듈 경계를 가로지르는 것만.

- 전투가 런 조립에서 슬롯 단위로 구성된다
- **상점에서 산 파츠가 바로 다음 전투에 등장한다**
- 상점에서 산 리릭이 다음 전투 오프닝을 바꾼다
- 이벤트가 준 사전 보너스가 1턴에 적용된다
- 승리 → 보상 → 다음 노드로 이어진다
- **박리 → Patch Loop 복구 왕복** (스킬 잠금·바닥 착지·복원 전부)
- 네 슬롯을 전부 벗기고 전부 되붙이면 원래 수치와 완전히 일치한다
- 보스가 두 페이즈를 거쳐 결말에 도달한다
- **Snip Lane 전체를 노드마다 자동 플레이해 종료 상태에 도달한다**
- Stitch Loop의 엘리트 노드가 실제로 엘리트 조우를 쓴다
- 런이 localStorage를 왕복하고, 끝난 런은 이어받지 않는다

## 4. E2E (Playwright)

브라우저에서만 검증 가능한 것들. 시드를 고정(`?seed=`)해 운에 의존하지 않는다.

| # | 검증 |
|---|---|
| 1 | 새 게임 → 작업대, 몸체 + 슬롯 4개 레이어가 DOM에 존재 |
| 2 | 파츠 교체 → 피규어의 `data-part-id`가 즉시 바뀐다 |
| 3 | **파츠 해제 → 해당 레이어가 DOM에서 사라진다** (opacity 트릭이 아님) |
| 4 | 전투 진입 → 의도 3개, 각각 이름과 위험도 배지 |
| 5 | 조립한 빌드가 전투 화면에 그대로 나타나고, 액션이 턴을 넘긴다 |
| 6 | Guard가 Block을 부여하고 UI가 보고한다 |
| 7 | **박리** — 바닥에 파츠가 놓이고, 무결성 행이 PEELED, 스킬 버튼이 비활성 + "박리됨", 레이어가 사라짐 |
| 8 | **Repair 복구** — PEELED 해제, 레이어 복귀, 바닥 비워짐 |
| 9 | 전투 클리어 → 보상 화면 → 다음 노드 |
| 10 | 이벤트 선택이 적용되고 런이 진행된다 |
| 11 | 상점 구매로 Scrap이 줄어든다 |
| 12 | **전투·이벤트·상점·보스를 거쳐 결과 화면까지 한 런 완주** |
| 13 | `/dev/assets`가 0 에러로 40개 이상 표시, 검색과 조정 도구 동작 |
| 14 | **누락 에셋이 게임을 깨뜨리지 않는다** — 네트워크에서 스프라이트를 차단하고 placeholder 로드 확인 |
| 15 | `/dev/data`가 0 콘텐츠 에러 |

7·8번은 Tape Roll(캐치 35%)과 Ribbon Knot(저항 +1)을 뺀 빌드로 싸우고,
피해를 주지 않는 Repair로 전투를 지연시켜 박리 압박이 쌓이게 한다 —
확률이 아니라 메커니즘을 시험하기 위해서다.

## 6. 시각 검수

```
npm run preview
node scripts/shoot.mjs screenshots
```

1440×900, 1280×720, 390×844(세로)에서 12개 화면을 촬영하고 콘솔 에러를 수집한다.
검수한 결과는 `docs/screenshots/`에 있다 — 1440×900 세트 12장과
세로 레이아웃 확인용 `13-battle-portrait.png`.

확인 항목: 이미지 잘림, 파츠 앵커, 레이어 순서, 글자 크기, 의도 가독성,
캐릭터가 UI보다 큰지, 레퍼런스 톤 유지, 관리자 대시보드처럼 보이지 않는지.

검수에서 잡아 고친 것:
- 1280×720에서 캐릭터가 무대 상단에 잘림 → 무대 높이에서 캐릭터 폭을 역산하도록 변경
- 의도와 액션 바가 접힘선 아래 → 수직 리듬 압축
- `fx.slash` 아이콘이 크림 배경에서 보이지 않음 (흰색) → 빨강으로 변경
- 상점의 리릭이 전부 같은 태그 아이콘 → 타입별 아이콘 매핑
- 같은 의도 카드 3장 → 의도 생성에 재추첨 규칙 추가
- 재부착이 낙하 애니메이션보다 빠를 때 레이어가 두 번 렌더 → 낙하 클론 즉시 제거
- 세로 화면이 축소된 데스크톱이었음 → 620 px 전용 레이아웃 추가
