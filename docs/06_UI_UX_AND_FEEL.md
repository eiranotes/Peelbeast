# 06 — UI / UX와 조작감

## 1. 시각 언어

레퍼런스 시트(`10_REFERENCE_IMAGE_MAPPING.md`)에서 가져온 규칙 세 가지:

1. **패널은 종이다.** 균일한 `border-radius`가 아니라 손으로 자른 듯한 `clip-path` 다각형과
   테이프 조각을 쓴다.
2. **글자는 크다.** 기계적 정보에 13 px 미만을 쓰지 않는다.
3. **캐릭터가 전투 화면에서 가장 크다.** 정보 패널이 캐릭터를 덮지 않는다.

토큰은 `src/styles/base.css`의 CSS 변수에 있다.
크림색 종이 `#f6ecd4`, 갈색 책상 `#8a6242`, 잉크 `#3a2b1e`, 빨강 `#b4533b`.

### 1.1 스티커 처리

모든 캐릭터·파츠 스프라이트는 **키스컷 스티커**다: 실루엣을 감싸는 두꺼운 오프화이트 테두리,
그 테두리에만 적용되는 손으로 자른 듯한 흔들림, 그리고 아래로 떨어지는 부드러운 그림자.
SVG 필터로 구현했다 (`scripts/lib/paper.mjs`) — 아트워크 자체는 흔들리지 않고 테두리만 흔들린다.

### 1.2 레퍼런스 아트의 사용

원본 v0.8 아트는 알파가 없는 회화적 스크린샷이라 캐릭터 위에 레이어로 올릴 수 없다
(그렇게 한 것이 v0.8의 실패였다). 대신 **책상에 테이프로 붙인 사진**으로 액자에 넣어 쓴다:

- 타이틀 — 배경 제거에 성공한 원본 스티커를 조립된 캐릭터 옆에 "ORIGINAL ART"로
- 전투 — 적 생체 정보 카드에 그 적의 원본 아트 초상
- 이벤트 / 상점 — 해당 장면의 원본 크롭을 액자로

이렇게 하면 업로드된 픽셀이 **원본 그대로** 게임 안에 보이면서도,
"레퍼런스 전체를 배경에 깔고 버튼만 얹는" 금지된 방식이 되지 않는다.

## 3. 전투 화면 구성

```
┌──────────────────────────────────────────────┬──────────┐
│ 플레이어 생체정보 │ 턴/Ink │ 적 생체정보(초상) │          │
├──────────────────────────────────────────────┤ 파츠     │
│                                              │ 무결성   │
│            무 대 — 캐릭터와 적                │          │
│         (책상 배경, 소품, 바닥의 벗겨진 파츠)  │ ────────  │
│                                              │ 로그     │
├──────────────────────────────────────────────┤ (접이식) │
│  적 의도 3개 (지금 / 다음 / 그다음)            │          │
├──────────────────────────────────────────────┴──────────┤
│  코어 4 + 스킬 4 — 큼직한 버튼 8개                       │
└─────────────────────────────────────────────────────────┘
```

무대 높이는 `clamp(250px, 42vh, 430px)`이고, 캐릭터 폭은 무대 높이에서 역산된다.
1280×720에서 캐릭터가 잘리지 않고 작아지며, 의도 레일이 접힘선 위에 남는다.

**로그는 보조 정보다.** 접을 수 있고, 화면의 주인공은 캐릭터와 의도 카드다.

### 3.1 의도 카드

각 카드가 보여주는 것: 아이콘, 이름, 예상 피해(타격 횟수 포함), 상태 부여(아이콘 + 이름 + 수치),
Glue 손실, Ink 증가, 적 Block 증가, **박리 대상 슬롯**, 박리를 막는 Block 임계값,
방어 가능/관통 여부, 그리고 위험도 4단계(경미/주의/위험/치명)를 왼쪽 색 띠와 배지로.

박리를 시도하는 의도는 자동으로 최소 "위험" 등급을 받는다.
`tests/unit/describe.test.ts`가 이를 강제한다.

## 4. 조작감

목표는 "버튼을 눌렀을 때 무언가 일어났다는 것이 몸으로 느껴지는 것"이다.
v0.8은 로그만 갱신되고 캐릭터가 정지해 있었다.

| 시점 | 반응 |
|---|---|
| ~0 ms | 버튼 눌림 변형 (`translateY(2px) scale(0.98)`) |
| 즉시 | 캐릭터 동작 시작 (공격 340 ms / 가드 400 ms / 수리 460 ms) |
| 충돌 | 화면 hit-stop 130 ms, 적 흔들림 + 밝기 플래시 380 ms |
| 충돌 | 피해 숫자가 1.1 s 동안 부양, 여러 개면 90 ms씩 시차 |
| 520 ms | 적 턴 시작 ("…" 표시) |
| 박리 시 | 파츠가 뜯겨 120° 회전하며 900 ms 낙하 → 책상 위 착지 애니메이션 |

모든 타이밍은 `BALANCE.feel`에 있다.

### 4.1 파츠 고유 아이들 모션

카탈로그의 `animationProfile`이 파츠마다 다른 정지 동작을 준다:
토스트는 부드럽게 튀고(`soft-bounce`), 우산은 흔들리고(`sway`),
가위와 폭탄은 미세하게 떨고(`jitter`), 유령은 뜨고(`float`), 테이프는 천천히 돈다(`spin-slow`).

## 5. 입력

### 5.1 키보드

전투는 클릭이 많은 화면이므로 단축키를 둔다. 액션은 실제 `<button>`이라
단축키는 대체가 아니라 **추가**다.

| 키 | 동작 |
|---|---|
| `1` `2` `3` `4` | Peel Strike / Guard / Repair / Press |
| `Q` `W` `E` `R` | Head / Hand / Core / Trinket 슬롯 스킬 |

각 버튼 우상단에 `<kbd>`로 표시되며, 터치 기기에서는 숨긴다.
입력 필드에 포커스가 있거나 플레이어 턴이 아니면 동작하지 않는다.

### 5.2 터치

터치에는 hover가 없어 작업대의 장착 전후 비교가 닿지 않았다.
`(hover: none), (pointer: coarse)` 를 감지해 **첫 탭은 미리보기, 두 번째 탭은 장착**으로 바꾼다.
미리보기 중에는 작업대 상단에 확정 버튼이 함께 뜬다.
마우스에서는 기존대로 hover 미리보기가 유지된다.

## 6. 반응형

| 폭 | 레이아웃 |
|---|---|
| > 1280 | 전투 2단 (무대 + 사이드 패널), 액션 8열, 작업대 2단 |
| ≤ 1280 | 전투 1단, 사이드 패널이 아래로, 액션 4열 |
| ≤ 900 | 생체정보 세로 적층, 의도 1열, 액션 2열, 레퍼런스 사진 숨김 |
| ≤ 620 | **세로 전용 레이아웃** — 축소된 데스크톱이 아니다 |
| 가로 ≤ 480 | 무대 축소, 사이드 패널 숨김 |

### 6.1 세로 전용 (≤ 620 px)

- 무대에서 **캐릭터와 적은 여전히 나란히** 둔다. 세로로 쌓으면 대치 구도가 사라진다
- 생체정보는 한 줄짜리 띠로 압축, 소품은 숨김
- 액션은 엄지로 닿는 2열 패드
- 작업대는 작업대 → 파츠 서랍 → 요약 → 경로 순서 (조작하는 것이 위로)
- 버튼 패딩을 키워 터치 타깃 확보

1440×900에서는 전투 화면 전체(생체정보·캐릭터·의도·액션)가 스크롤 없이 들어간다.
1280×720에서는 의도까지 보이고 액션 바 일부가 접힘선 아래로 간다 —
캐릭터 크기를 유지하기 위한 의도적 트레이드오프다.

## 7. 접근성

- 모든 게임플레이 이미지에 `alt`, 장식 이미지에 `aria-hidden`
- 액션은 실제 `<button>` — 키보드 탭 순회와 스크린리더가 그대로 동작한다
  (캔버스 렌더러를 쓰지 않은 이유 중 하나)
- 슬롯 탭은 `role="tablist"` + `aria-selected`
- `prefers-reduced-motion`에서 애니메이션 전부 1 ms로 축약
- 상태 칩은 아이콘 + 이름 + 수치를 함께 보여준다. 색만으로 정보를 전달하지 않는다

## 8. 남은 UX 과제

- 세로 레이아웃에서 생체정보 3단이 화면의 절반을 차지한다. 접이식으로 만들 여지가 있다
- 사운드 없음
- 튜토리얼 없음
- UI 문구가 한국어로 하드코딩되어 있다
