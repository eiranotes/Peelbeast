# 09 — 버전 이력과 로드맵

## 1. 이력

v0.1~v0.8의 원본 기록은 `docs/legacy/v0.8/01_VERSION_HISTORY.md`에 보존되어 있다. 요약:

| 버전 | 내용 |
|---|---|
| v0.1~v0.4 | 정적 웹 데모 → 모바일 레이아웃 시도 → 이미지 에셋 기반 전환 → 레이어드 장착 실험 |
| v0.5~v0.6 | 첫 턴제 전투 프로토타입 → 파츠/적/상태 밀도 증가, 박리 로직 강화 |
| v0.7 | 루트 선택, 다중 전투 노드, 보상, 리릭 누적 |
| v0.8 | 이벤트·상점·엘리트·Scrap·캐리오버. 버티컬 슬라이스 |
| **v0.9** | **전면 재구현.** 단일 HTML → Vite/TS/React, 데이터 기반 콘텐츠, 시드 RNG, 에셋 카탈로그, 테스트 131 |

### v0.9에서 한 것

- 저장소 감사 (`docs/analysis/CURRENT_REPOSITORY_AUDIT.md`)
- 아키텍처 재설계: 엔진/데이터/UI 분리, 순수 리졸버, `FxEvent` 기반 연출
- 파츠 효과를 코드에서 데이터로 (`Effect[]`, `PassiveRule[]`)
- 적 의도의 표시/실행 이중 정의 제거
- 시드 RNG로 결정론 확보 (`?seed=` 지원)
- 에셋 카탈로그 + fallback + `/dev/assets` 조정 도구 + 자동 아틀라스 생성
- 알파 채널을 가진 스프라이트 49종 신규 저작, v0.8 레퍼런스에서 원본 스티커 1종 복원
- 시너지 시스템 신규 (v0.8에는 UI 라벨만 있었다)
- 죽어 있던 `vulnerable` / `insight` 상태에 실제 규칙 부여
- 독립 작업대 화면 (전투 중 교체로 전투가 리셋되던 익스플로잇 제거)
- localStorage 저장/이어하기
- 적 4종(신규 Clip Moth 포함), 조우 6종, 이벤트 6종, 리릭 10종으로 확장
- 테스트 135개, 시각 검수 24장
- 밸런스 시뮬레이터 (`npm run simulate`) 와 1차 밸런싱 패스

## 2. 다음 우선순위

### P0 — v0.95 이전에 반드시

1. **최종 아트 교체.** 현재 스프라이트 48종은 `placeholder` 상태다.
   `05_ASSET_CATALOG_SPEC.md` §6의 5단계 절차로 교체한다.
   적 3종은 특히 원본 회화 아트로 교체해야 한다 — 자동 배경 제거가 실패한 대상이다.
2. **밸런싱 2차.** 1차는 끝났다 (`02_GAME_DESIGN.md` §8.3 — 전 조합 승률 0 %에서
   0~62.5 %로). 남은 것: 전투 길이를 11~16턴에서 목표인 4~9턴으로 줄이는 것,
   `box/umbrella/tape/patch` 같은 순수 방어 빌드에 승리 조건을 주는 것,
   너무 쉬운 `moth` 조정. `npm run simulate` 로 측정한다.
3. **모바일 세로 레이아웃.** 현재는 축소된 데스크톱이다.
   터치에서 파츠 호버 미리보기가 동작하지 않는 것도 함께 해결한다.

### P1 — v1.0을 위해

4. 콘텐츠 확장: 파츠 12 → 24, 적 4 → 8, 이벤트 6 → 15, 보스 1 → 2
5. 튜토리얼 (첫 전투에서 박리를 반드시 한 번 경험시키는 스크립트 전투)
6. 사운드 최소 도입 (박리·재부착·타격 3종만으로도 체감이 크게 달라진다)
7. 시각 회귀 테스트 (스크린샷 diff)
8. 컴포넌트 단위 테스트

### P2 — 이후

9. 메타 진행 (해금 중심, 수치 성장은 지양)
10. 도감 (파츠/적), 조합 프리셋 저장
11. 난이도 단계

## 4. 최종 제품 방향

"가볍게 시작하지만 빌드 고민이 깊은, 귀여운 파츠 조립형 로그라이크."

네 기둥은 v0.8 문서에서 그대로 가져왔고 여전히 유효하다:

1. 파츠 조합의 재미
2. 전투 중 파츠가 실제로 망가지는 긴장감
3. 짧은 런 단위 반복 플레이
4. 시각적으로 기억나는 종이 공예 감성

플랫폼 우선순위: 웹/데스크톱 프로토타입 검증 → 모바일 UI 재설계 → 패키지형 소형 게임 검토.
